# 架构与约定

> 秒杀组的仓库规范。新人提交代码前先读一遍，review 时按这个卡。

## 1. 分层架构

严格三层，依赖方向单向向下，不许跨层、不许反向依赖：

```
controller  →  service  →  mapper  →  (XML SQL)  →  MySQL
```

| 层 | 职责 | 不该做什么 |
|----|------|-----------|
| `controller` | 收 HTTP 参数、调 service、包 `ApiResponse`、映射 HTTP 状态码 | 不写业务逻辑、不直接调 mapper、不碰事务 |
| `service` | 业务逻辑、**事务边界**（`@Transactional`）、编排多个 mapper | 不感知 HTTP、不返回 `ApiResponse` |
| `mapper` | 数据访问接口（只有方法签名） | 不写业务逻辑 |
| `mapper/*.xml` | 手写 SQL | 不藏业务判断（业务放 service） |

**事务只打在 service 层**。原因：controller 层加事务会把 HTTP 处理时间算进事务、拉长持锁时间；
mapper 层太细、无法覆盖「多步操作」。

## 2. 包结构约定

```
com.devteam.seckill
├─ controller   @RestController，一个资源一个 controller
├─ service      业务接口/实现（本项目从简，直接类）
├─ mapper       @Mapper 接口，与 resources/mapper/*.xml 一一对应
├─ domain       实体（Product / SeckillOrder / User）
│  └─ dto       出入参对象（ApiResponse 等）
└─ config       配置类（RedisConfig / WebConfig）
```

## 3. 命名约定

- 类：`大驼峰`（`ProductService`）。
- 方法/变量：`小驼峰`（`selectById`）。
- Mapper 查询方法：`selectXxx` / `countXxx` / `insertXxx` / `updateXxx` / `deleteXxx`。
- 数据库列：`snake_case`（`category_id`）；Java 字段：`camelCase`（`categoryId`）。
  靠 `map-underscore-to-camel-case: true` 自动映射，**不要手写一堆 `<result>` 除非列名对不上**。
- 索引名：`idx_<表>_<用途>`（如 `idx_product_search`）；唯一索引：`uk_<列...>`。

## 4. MyBatis SQL 约定

- **手写 SQL，禁止 MyBatis-Plus / JPA 自动生成**。本项目要让你看见每一条 SQL、每一个索引、每一次加锁。
- 参数一律用 `#{}`（预编译，防注入），**禁止 `${}`**（字符串拼接，SQL 注入风险），除非是动态表名/排序列且你能保证安全。
- 一个 `<select>` 对应一个 mapper 方法，`id` 必须与方法名完全一致。
- 复杂 SQL 用 `<sql>` 片段 + `<include>` 复用列清单。

## 5. API 响应约定

统一用 `ApiResponse<T>` 包装：

```json
{ "code": 0, "message": "ok", "data": { ... } }
```

- `code=0` 成功；非 0 为业务错误码。
- HTTP 状态码语义：200 正常、404 资源不存在、501 功能未实现（Stage 0/1 的下单接口）。

## 6. 测试约定（红绿驱动）

- 每个阶段一个 `@Tag("stageNN")`，用 `mvn test -Dgroups=stageNN` 单跑。
- **验收测试初始为红**（功能没写），你实现后变绿——这是「工单完成」的客观信号。
- 测试连**真 MySQL**（不用 H2/Testcontainers），因为要复现 InnoDB 的索引/锁/MVCC 真实行为。
- 测试必须**可重复**：`@BeforeEach` 清理并重置 fixture，索引用幂等 DDL。
- 并发模拟器用 `@Tag("sim")`，默认被 Surefire 排除，跑时 `-Dgroups=sim -Dtest.excludedGroups=`。

## 7. 提交规范（Conventional Commits 简化版）

```
<type>(<scope>): <subject>

type:  feat | fix | docs | test | refactor | chore
scope: stage1 | seckill | product | docker | ...
```

例：
```
feat(stage1): 实现 searchProducts 并添加 idx_product_search 联合索引
test(stage1): 补充 EXPLAIN 命中索引断言
```

- 一张工单对应一组提交，别把 Stage 1 和 Stage 2 混在一个 commit。
- **参考解只进 `solutions` 分支，绝不进 `main`**（防剧透）。

## 8. 配置与环境变量

所有连接参数都支持环境变量覆盖（`application.yml` 里的 `${VAR:default}`）：

| 变量 | 默认 | 说明 |
|------|------|------|
| `DB_HOST` | localhost | MySQL 主机 |
| `DB_PORT` | 13306 | MySQL 端口（避开 VM 上的 5432） |
| `DB_NAME` | seckill_lab | 库名 |
| `DB_USER` / `DB_PASSWORD` | root / bagu1234 | 账号 |
| `REDIS_HOST` / `REDIS_PORT` | localhost / 16379 | Redis |
| `SERVER_PORT` | 8080 | 应用端口 |

> 绝不把真实生产密钥写进仓库。本项目的 `bagu1234` 只是本地教学用，别拿去当生产密码。
