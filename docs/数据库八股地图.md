## Stage 1 · 索引 & 执行计划 🟥

**亲手场景**：商品搜索查询慢 → 你写 MyBatis 查询 + 建联合索引 + 用 EXPLAIN 证明命中。

| 考点 | 一句话原理 | 面试题 |
|------|-----------|--------|
| B+ 树索引 | 矮胖多叉树、叶子节点存数据/指针且有序链表相连，适合磁盘块读取与范围查询 | 为什么 MySQL 用 B+ 树而不是 B 树/红黑树/Hash？ |
| 聚簇 vs 二级索引 | InnoDB 主键索引叶子存整行(聚簇)；二级索引叶子存主键，需「回表」 | 什么是回表？怎么避免？ |
| 最左前缀 | 联合索引 `(a,b,c)` 必须从 a 开始连续命中 | `WHERE b=? AND c=?` 能用 `(a,b,c)` 索引吗？ |
| 覆盖索引 | 查询列全在索引里，不回表，`Extra: Using index` | 如何用覆盖索引优化 `SELECT` 性能？ |
| 索引失效 | 列上函数/运算、隐式类型转换、前导 `%`、`OR` 带非索引列 | 哪些写法会导致索引失效？ |
| EXPLAIN | `type`(const>ref>range>index>ALL)、`key`、`rows`、`Extra` | EXPLAIN 主要看哪些字段？type=ALL 意味着什么？ |
| 索引下推 ICP | 联合索引里 `WHERE` 条件在存储引擎层先过滤，减少回表 | 什么是索引下推？ |

**复现命令**：
```sql
-- 建索引前
EXPLAIN SELECT ... FROM product WHERE category_id=10 AND status=1 AND price BETWEEN 50 AND 200 ORDER BY price LIMIT 20;
-- 期望 type=ALL, key=NULL
-- 建索引后（idx_product_search）
-- 期望 type=range/ref, key=idx_product_search
```

## Stage 2 · 事务 ACID & 传播 ⬜

**亲手场景**：扣库存 + 建订单必须原子 → 你用 `@Transactional` 实现，中途异常要整体回滚。

| 考点 | 一句话原理 | 面试题 |
|------|-----------|--------|
| ACID | 原子性(undo log)/一致性/隔离性(锁+MVCC)/持久性(redo log) | ACID 分别靠什么机制保证？ |
| autocommit | 默认每条语句一个事务；`@Transactional` 关掉它、手动 commit | Spring 事务底层做了什么？ |
| 传播行为 | REQUIRED(默认,加入或新建)/REQUIRES_NEW(挂起外层新建)/NESTED(保存点) | A 方法调 B 方法，B 的异常会不会回滚 A？ |
| 回滚规则 | 默认只回滚 RuntimeException；受检异常要 `rollbackFor` | `@Transactional` 什么情况下不生效？ |
| 事务失效 | 方法非 public、自调用(绕过代理)、异常被 catch 吞掉、多线程 | 列举 @Transactional 失效的场景 |
| undo/redo log | undo 保证原子性+MVCC 旧版本；redo 保证持久性(crash-safe) | 事务提交后宕机，数据会丢吗？ |

## Stage 3 · 锁 & 超卖 ⬜

**亲手场景**：100 线程抢 10 库存，先复现超卖 → 用悲观锁/乐观锁修复 → 成功恰好 10、库存 0。

| 考点 | 一句话原理 | 面试题 |
|------|-----------|--------|
| 丢失更新 | 两事务读同值→各自改→后写覆盖先写 | 超卖的根因是什么？ |
| 悲观锁 | `SELECT ... FOR UPDATE` 先锁行再改，阻塞其他事务 | FOR UPDATE 加了什么锁？ |
| 乐观锁 | `version` 字段或 `UPDATE ... SET stock=stock-1 WHERE stock>0`，靠 CAS | 乐观锁 vs 悲观锁怎么选？ |
| 行锁 vs 表锁 | InnoDB 行锁基于索引；无索引命中会退化成锁全表 | 什么情况下行锁变表锁？ |
| 共享/排他锁 | S 锁(读)可共存，X 锁(写)互斥 | 读写锁的兼容矩阵？ |
| 死锁 | 两事务互相等对方的锁 → InnoDB 检测并回滚代价小的一方 | 如何排查/避免死锁？ |

**复现命令**：`mvn test -Dgroups=sim -Dtest.excludedGroups=`（并发模拟器）

## Stage 4 · 隔离级别 & MVCC ⬜

**亲手场景**：对账读到脏数据/同一事务内两次读不一致 → 你调隔离级别 + 复现脏读/不可重复读/幻读。

| 考点 | 一句话原理 | 面试题 |
|------|-----------|--------|
| 四隔离级别 | READ UNCOMMITTED / READ COMMITTED / **REPEATABLE READ(InnoDB默认)** / SERIALIZABLE | 各级别分别解决什么并发问题？ |
| 脏读 | 读到别的事务未提交的数据 | RU 为什么会脏读？ |
| 不可重复读 | 同事务内两次读同一行结果不同(别人改了并提交) | RC 能避免不可重复读吗？ |
| 幻读 | 同事务内两次范围查询行数不同(别人插了并提交) | RR 能完全避免幻读吗？ |
| MVCC | 每行有隐藏 `trx_id`+`roll_pointer`，undo log 组成版本链 | MVCC 如何实现快照读？ |
| ReadView | 事务读时生成可见性快照(m_ids/min/max/creator) | RR 和 RC 的 ReadView 生成时机有何不同？ |
| 快照读 vs 当前读 | 普通 SELECT 是快照读；`FOR UPDATE`/`UPDATE` 是当前读 | RR 下幻读到底存不存在？(快照读靠MVCC,当前读靠Next-Key Lock) |
| Next-Key Lock | 行锁 + 间隙锁，锁住范围防止插入 | RR 如何用 Next-Key Lock 防幻读？ |

## Stage 5 · Redis 缓存三件套 ⬜

**亲手场景**：热点商品打挂 DB → 引入 Redis 缓存，处理穿透/击穿/雪崩 + 缓存一致性。

| 考点 | 一句话原理 | 面试题 |
|------|-----------|--------|
| 缓存穿透 | 查一个**根本不存在**的数据，缓存和 DB 都没有，请求全打 DB | 穿透怎么办？(空值缓存/布隆过滤器) |
| 缓存击穿 | 某个**热点 key 过期瞬间**，大量并发同时打 DB | 击穿怎么办？(互斥锁重建/逻辑过期) |
| 缓存雪崩 | **大量 key 同时过期**或 Redis 宕机，DB 被打垮 | 雪崩怎么办？(随机TTL/多级缓存/熔断) |
| 缓存一致性 | 先更 DB 再删缓存(Cache Aside)；延迟双删 | 为什么是删缓存不是更新缓存？ |
| Redis 数据结构 | String/Hash/ZSet 等在秒杀场景的用法 | 库存预扣为什么常用 Redis？ |
| 持久化 | RDB(快照) vs AOF(追加日志) | Redis 宕机数据会丢吗？ |

## Stage 6（选修）· 死锁 & 分布式锁 ⬜

**亲手场景**：复现交叉更新死锁 + 优化加锁顺序；用 `SET NX PX` + Lua 实现 Redis 分布式锁。

| 考点 | 一句话原理 | 面试题 |
|------|-----------|--------|
| 间隙锁 Gap Lock | 锁住索引区间之间的「空隙」，防止插入(RR 特有) | 间隙锁什么时候加？ |
| 死锁排查 | `SHOW ENGINE INNODB STATUS` 看 LATEST DETECTED DEADLOCK | 线上死锁怎么定位？ |
| 加锁顺序 | 多行更新按固定顺序(如按主键升序)加锁，避免交叉等待 | 如何从代码层面避免死锁？ |
| 分布式锁 | `SET key val NX PX ttl`，value 存唯一标识，Lua 原子释放 | 为什么释放锁要用 Lua？ |
| 锁续期 | 业务没执行完锁先过期 → 看门狗续期(Redisson) | 分布式锁的续期问题怎么解决？ |
| Redlock | 多个独立 Redis 节点投票加锁(有争议) | Redlock 靠谱吗？ |

## 附：本项目**不涉及**、但你该文字了解的考点

- **分库分表**：水平/垂直拆分、分片键选择、跨库 JOIN/分页难题、扩容迁移。
- **主从复制**：binlog(ROW/STATEMENT/MIXED) → relay log → 重放；主从延迟；读写分离。
- **binlog 三种格式**：Statement(省空间可能不一致)/Row(准确费空间)/Mixed。
- **两阶段提交**：redo log 与 binlog 的一致性(prepare → write binlog → commit)。

> 这些在 `my.cnf`(已开 `log_bin` ROW)基础上可以文字讨论，本项目不搭实机，避免范围膨胀。
